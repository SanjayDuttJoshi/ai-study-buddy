FOLDER STRUCTURE TO CREATE (Modular Design)
-------------------------------------------

frontend/
├── utils/                    # Shared utilities
│   ├── __init__.py
│   ├── api_client.py         # Backend API communication
│   └── session.py            # Session state management
├── pages/                    # Feature-based pages
│   ├── __init__.py
│   ├── login.py              # LOGIN FEATURE: Login form UI
│   ├── register.py           # REGISTER FEATURE: Registration form UI
│   ├── dashboard.py          # DASHBOARD: Main page after login
│   └── (Future: notes.py, summaries.py, chat.py, quizzes.py)
└── app.py                    # ONLY routing & navigation (minimal)

PRINCIPLE: Each feature = One page file
- app.py → Routing logic only (if authenticated → dashboard, else → login)
- login.py → Complete login UI & logic
- register.py → Complete registration UI & logic  
- dashboard.py → Dashboard UI after login
- Each page is self-contained and focused!

WHY MODULAR?
✓ app.py stays clean (no huge file with 1000+ lines)
✓ Easy to find UI code (login UI? check login.py)
✓ Easy to test (test login? just load login.py)
✓ Reusable (import login.show() anywhere)
✓ Team-friendly (Person A on login.py, Person B on dashboard.py)
✓ Future-proof (add chat? just add chat.py)

TASK DIVISION
-------------------------------------------

PERSON A - API Integration & Session:
---------------------------------
Tasks:
1. Create utils/api_client.py
   - APIClient class
   - register() method → Call POST /auth/register
   - login() method → Call POST /auth/login
   - get_current_user() method → Call GET /auth/me
   - Error handling for API calls
   
2. Create utils/session.py
   - init_session() → Initialize session state
   - login_user() → Save token and username
   - logout_user() → Clear session
   - is_authenticated() → Check login status
   - get_token() → Get current token

What to learn:

- Session state management
- JWT token handling

-------------------------------------------
VALIDATION RULES
-------------------------------------------

Registration:
- Username: 3-50 characters
- Email: Must contain @
- Password: Minimum 6 characters
- Confirm password must match

Login:
- Username: Required
- Password: Required

All forms:
- Show helpful error messages
- Disable submit during API call
- Show success message after action

-------------------------------------------
USER FLOW (Page Navigation)
-------------------------------------------

1. User opens app (app.py checks authentication)
   → NOT authenticated → Show Login/Register tabs
   
2. NEW USER PATH:
   - Click Register tab → pages/register.py shows
   - Fill form → Validate → Call API → Success message
   - Switch to Login tab → pages/login.py shows
   
3. EXISTING USER PATH:
   - Stay on Login tab → pages/login.py shows
   - Enter credentials → Call API → Get token
   - Token saved via session.login_user()
   - app.py detects authenticated → Show dashboard
   
4. LOGGED IN:
   - pages/dashboard.py shows
   - Display user info (from session)
   - Can navigate (future: notes, summaries, etc.)
   - Logout button → session.logout_user()
   - app.py detects NOT authenticated → Back to login

FILE FLOW:
app.py → checks auth → routes to correct page
pages/login.py → handles login
pages/register.py → handles registration  
pages/dashboard.py → main app after login

-------------------------------------------
COMMON CHALLENGES
-------------------------------------------

1. Backend not connecting → Check backend is running (port 8000)
2. Session not persisting → Make sure init_session() is called
3. Forms not clearing → Use clear_on_submit=True
4. Page not refreshing → Use st.rerun() after state changes
5. API errors → Check request format (JSON vs form-data)

-------------------------------------------
UI/UX TIPS
-------------------------------------------

Good Practices:
✓ Always show loading spinner during API calls
✓ Use emojis for visual appeal (✅ ❌ 👤 🔐)
✓ Color-code messages (green=success, red=error, blue=info)
✓ Clear error messages ("Username already exists" not "400 error")
✓ Celebrate success (st.balloons() after registration!)
✓ Use st.expander() for additional info
✓ Good spacing between elements
